# apps/web

클라이언트. 판을 그리고, 개입 순간을 연출하고, 복기 화면에서 분기를 보여준다. 설계는 [docs/03-frontend.md](../../docs/03-frontend.md).

## 실행

서버와 클라이언트를 각각 띄운다.

```sh
cd apps/server && go run ./cmd/api   # :8080
pnpm dev                             # :5173 (레포 루트에서)
```

개발 서버는 `/healthz` · `/api` · `/ws`를 `http://localhost:8080`으로 프록시한다. 서버를 다른 포트로 띄웠다면 `SERVER_ORIGIN=http://127.0.0.1:9000 pnpm dev`.

프록시를 두는 이유는 클라이언트가 개발·배포에서 똑같은 상대 경로를 쓰게 하려는 것이다. `ws://localhost:8080/ws` 같은 절대 주소를 코드에 적으면 배포 때 갈라진다.

> `localhost:8080`에 다른 것이 이미 떠 있으면 프록시가 그쪽으로 간다. 특히 Node가 `localhost`를 IPv6(`::1`)로 먼저 풀기 때문에, IPv4에만 바인딩한 서버는 조용히 지나친다. 그럴 때는 `SERVER_ORIGIN`에 `127.0.0.1`을 명시할 것.

## 언어

**화면에 나가는 문자열은 전부 일본어다.** 사용자는 일본인이다. 주석과 이 문서는 한글이지만, JSX 안의 텍스트·에러 메시지·빈 상태 문구에 한글이 섞이면 안 된다.

`index.html`의 `lang="ja"`와 `index.css`의 폰트 스택(Hiragino / Noto Sans JP)이 그 전제 위에 있다.

## 좌표

쇼기는 두 축의 이름과 방향이 다르다. **筋(file)은 오른쪽부터 1~9**, 段(rank)은 위부터 1~9다. 화면 배열은 사람이 판을 보는 순서대로 왼쪽 위(9筋 1段)부터 행 우선으로 깐다.

그래서 `index = (rank-1)*9 + (9-file)`이고, `9-file`이 이 도메인에서 가장 자주 틀리는 지점이다. `square.test.ts`가 81칸을 전부 왕복 검사하는 이유가 그것이다.

사람이 읽는 표기(「7六」)와 엔진이 쓰는 USI 표기(`7f`)가 다르다는 것도 주의. 段만 a~i로 바뀐다.

## 아직 없는 것

판 렌더링, 대국 연결(`/ws`), three.js 장면. 지금 `App.tsx`가 하는 일은 서버까지 경로가 뚫려 있는지 확인하는 것뿐이다.

three.js는 의존성만 들어와 있고 아직 쓰지 않는다. 쓸 곳은 [利き 히트맵과 개입 연출 두 컷](../../docs/03-frontend.md)뿐이고, 판 자체는 정사영 카메라로 2D처럼 읽히게 그린다.
