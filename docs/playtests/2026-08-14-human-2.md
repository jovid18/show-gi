**8건 전부 LLM 실호출이다.** 회차 1의 `NULL` 25건은 OrcaRouter 장애였고([회차 1 §5](2026-08-13-human-1.md)), 이 판에서는 그 일이 없었다. 모델은 전부 `gemini-3.5-flash-lite`.

**그런데 문구 형식은 그대로 흔들렸다**(회차 1 #13). 같은 판 · 같은 모델 · 전부 정상 호출인데 숫자 표기가 네 가지다:

```
▲2二歩成なら、相手は△7八角成で、形勢は-123です。
▲2三歩と指すと、相手は△2一金と指して、形勢はマイナス601です。
▲6九歩なら相手は△5六銀で、形勢は+323です。
そのあと▲6九歩と指すと、相手は△5六銀と指して形勢は-961です。
```

**이것이 이 회차의 새 사실이다.** 회차 1은 형식 흔들림을 라우터 장애와 섞어 봤는데, **장애가 없어도 흔들린다.** 원인은 라우터가 아니라 프롬프트·후처리에 있다.

문구 하나는 **이유를 못 찾았다고 스스로 말한다** — 11手의 `other` 개입이 「この手は形勢が大きく悪くなります。**理由は特定できていません。**」로 시작한다. `other` 카테고리가 87.5%인 판에서 이 문장이 나가는 자리가 어디인지를 봐야 한다.

**`cost_yen` 이 8건 전부 0이다.** 회차 1과 같고, 계측 문제인지 모델이 정말 0인지는 여전히 확인 전이다 **[미확정]**.

### 총평은 이번엔 결과를 맞게 말했다

```

次はタダ捨てに気をつけましょう。
```

회차 1의 「終盤で崩れた」(이기는 판의 投了를 그렇게 말한 것, #16)와 달리 **이 판은 실제로 이겼고 총평도 이겼다고 말한다.** 다만 사람이 요구한 것은 그 위다 — **어느 국면을 보라고 짚어 주는 것**(아래 #2).

### 실력 추정치 — 판 하나로 얼마나 움직이나

|                           | 판 시작 전                     | 판 끝난 뒤    |
| ------------------------- | ------------------------------ | ------------- |
| `skill_loss`              | `NULL`(모름 → `PriorLoss` 0.5) | **0.368**     |
| `skill_samples`           | 0                              | **60**        |
| `skillShift`              | 0cp                            | **−79cp**     |
| 화면 눈금(`strengthStep`) | `ふつう`(3)                    | **`強め`(4)** |

**평형식이 두 번째 표본에서도 맞았다.** EWMA의 정지점은 블런더율 `r` 에 대해 `0.5·r·(1−L) = 0.1·(1−r)·L` 이고:

|              | 블런더율 | 예측 `L` | 실제 `skill_loss` |
| ------------ | -------- | -------- | ----------------- |
| 회차 1 (397) | 30%      | 0.682    | **0.658**         |
| 회차 2 (580) | 13.3%    | 0.434    | **0.368**         |

**`skill_loss` 는 실력의 누적이 아니라 블런더율의 평형값이다.** `RiseRate`·`FallRate` 를 실측으로 잡을 때 이 관계가 자가 된다 — 두 상수를 고르는 것이 곧 「블런더율 몇 %를 어느 눈금으로 볼 것인가」를 고르는 것이다.

> **판 사이로 넘어온 값이 다른 세션의 착수로 오염될 수 있다.** 이 판을 시작하기 전에 실제로 그랬다 — 회차 1이 끝날 때 0.658이던 값이 다음 판 시작 시점에 **0.250**이었고, 그 사이 user 64로 들어온 것은 확인용 착수(`games.id=547` · `579`)뿐이었다. **정석 구간의 조용한 수는 낙폭이 0에 가까워 「매 수 최선」으로 셈된다**(`moveLoss`). `FallRate=0.1` 로도 조용한 수 16개면 값이 5분의 1이 된다.
>
> 사람이 두는 판마다 이것을 손으로 비울 수는 없다. **표본 수를 신뢰도로 쓰지 않는 것**이 여기 걸린다 — `skillShift` 는 `Ready()`(표본 ≥3)만 확인하고, 그 뒤로는 표본 3개짜리 추정과 246개짜리 추정을 똑같이 믿는다.
