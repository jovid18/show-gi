# 플레이테스트 회차 목록

에이전트 셋이 prod에서 한 판씩 두고 남긴 기록이다. 실행은 `/playtest` 스킬이 한다([.claude/skills/playtest](../../.claude/skills/playtest/SKILL.md)).

**이 폴더는 사실 기록이다.** 설계는 [01-core.md](../01-core.md)에, 지금 상태는 [06-status.md](../06-status.md)에 있다. 회차 문서는 **덮어쓰지 않는다** — 과거 기록이 남아야 「문구를 고친 뒤 실제로 나아졌나」를 볼 수 있다.

수동으로 한 판 둔 선행 기록은 [08-playtest.md](../08-playtest.md)에 있다. 회차 문서의 구조와 평가 항목은 그것을 따른다.

## 회차

| ----------- | --- | ---- | ------------ | --------- |
| _아직 없음_ |     |      |              |           |

## 읽는 법

- **`other` 비율**이 가장 중요한 추세다. 이유를 못 대는 개입이 줄어드는 것이 곧 제품이 나아지는 것이다. 기준선은 [06-status.md](../06-status.md) §17의 65~70%이고, 수동 1판(08-playtest.md)에서 66.7%였다
- **힌트 계단이 몇 단계까지 열렸나**는 「스스로 찾게 두는가」의 지표다. 매번 마지막 단계까지 열린다면 그 앞 단계들이 일을 못 하고 있는 것이다
- **에이전트가 틀린 이유**가 카테고리 설계의 입력이다. 같은 유형이 회차마다 반복되면 그 유형에 카테고리가 필요하다는 뜻이다

## 주의

- 회차 문서의 숫자는 **prod DB에서 꺼낸 것**이어야 한다. 에이전트의 기억으로 적지 않는다
- 브라우저 화면을 보지 않고 프록시로만 두므로, **렌더된 카드의 가독성은 매번 `[미확정]`**이다. 그것은 따로 검증해야 한다
