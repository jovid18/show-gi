## 2. 발표 / 영상 구성

8개 기준을 순서대로 훑지 말 것. **6-7-4를 한 덩어리로 묶어 클라이맥스로.**

| 순서 | 내용                                                                                   | 시간 |
| ---- | -------------------------------------------------------------------------------------- | ---- |
| 1    | 문제 — 초심자가 블런더로 무너지는 장면                                                 | 30초 |
| 2    | **데모 — 개입 루프. 여기서 승부가 끝난다**                                             | 2분  |
| 3    | 왜 이 구조인가 — 판단은 엔진, 표현은 LLM → **정확성·비용·안전성이 한 설계에서 동시에** |      |
| 4    | 개입 타이밍은 차세대 AI 공통 문제 (기준 8)                                             |      |
| 5    | 시장 숫자 (ウォーズ 800만 유저 / 棋神ラーニング 월 1,200엔)                            |      |

**첫 30초 안에 블런더 개입 장면이 나와야 한다.** 쇼기 규칙 설명부터 시작하면 진다.

## 3. 미결 사항

- [ ] 블런더 카테고리 온톨로지 확정 — 몇 개? 분류 룰 경계는?
- [ ] 승률 변환 상수 K — 초기 600, 실측으로 보정. **엔진이 水匠5로 바뀌었으니 그 cp 척도 위에서 잡는다**
- [ ] 레이팅 온라인 갱신식
- [ ] 수준별 개입 임계치 초기값 검증 (현 4단계)
- [ ] 手筋 힌트 발동 임계치 (300cp는 아직 감)
- [x] ~~종반 판정의 詰み 탐색 지평~~ — **`DepthLimit=7`, 평균 107ms**로 실측했다. 남은 것은 **「크게 멀어졌다」의 기준** — 승률 낙폭이 포화하는 구간이라 기준을 詰み 거리로 바꾸기로 했다([개입 엔진 §2](01-core.md))
- [x] ~~엔진 호출 레이턴시 예산 실측~~ — **끝. k=10으로 정했다** ([적응형 상대](01-core.md)). 재측정은 `internal/usi/measure_test.go`. 남은 것: 선행 계산 깊이(14는 8.4초라 12로 내릴지)와 **초반 캐시 히트율**
- [ ] **評価関数 비교** — 探索部는 やねうら王으로 정했지만 얹을 평가함수가 미정이다. 水匠·elmo 등 후보를 같은 국면 묶음에 돌려 cp가 얼마나 갈리는지 본다. 블런더 임계치가 여기에 통째로 종속이라 **D3 상수를 잡기 전에** 끝나야 한다
- [x] ~~水匠 평가함수 파일의 재배포 라이선스 확인~~ — **水匠5는 やねうら王 릴리스에서 무료 공개**된 단체 파일이고 GPLv3다. 최신 水匠은 지원자 전용이라 못 쓴다. 이미지 빌드 시 릴리스에서 받는다
