# Zenn 기사 — 종합편 한 편

마감 전 공개할 글은 **종합 기사 한 편**으로 정했다(2026-08-14). 여러 편을 쓰면 각 글이 구체적인 기술 주제에는
강해지지만, 지금은 쓸 시간도 독자가 시리즈를 따라올 근거도 없다. 제품을 처음 보는 사람이 한 글에서 문제·체험·설계를
전부 이해하게 하는 쪽을 택한다.

기존 기술 초안 세 편은 공개하지 않는다. 전부 `published: false`인 채로 남겨 사실과 실측을 꺼내 보는 내부 기술 메모로만
쓴다.

## 1. 공개 후보

| 항목 | 값                                                                           |
| ---- | ---------------------------------------------------------------------------- |
| 파일 | `articles/showgi-ai-knows-when-to-interrupt.md`                              |
| 제목 | `AIは「何を言うか」より「いつ黙るか」——将棋コーチ show-gi を作った`          |
| 형태 | 제품 소개와 핵심 기술 의사결정을 잇는 종합 기사 한 편                        |
| 독자 | AI 제품을 만드는 개발자, 학습 서비스의 개입 UX에 관심 있는 사람, 쇼기 초심자 |
| 공개 | `published: true`. 이 변경이 Zenn 연동 브랜치 `main`에 머지되면 공개된다     |

기능편과 개발편으로 둘을 나누는 것은 **종합편이 너무 길어 각각 독립된 질문과 결론을 가질 때만** 고려한다. 지금은 두 번째
글을 일정에 넣지 않는다.

## 2. 한 편의 중심 질문

**AI가 무엇을 말할지가 아니라, 언제 개입하고 언제 침묵해야 하는가.**

기능과 기술을 따로 나열하지 않고 이 질문에 대한 선택으로 연결한다.

1. 기존 쇼기 AI의 공백 — 약한 상대는 자멸하고 강한 상대는 한 번의 실수를 놓치지 않는다
2. 제품 경험 — 큰 실수에서만 멈추고, 이유를 말하고, 다시 두게 한다
3. 판단은 엔진, 표현만 LLM — 초심자가 검증할 수 없는 설명을 LLM에 맡기지 않는다
4. 승률 낙폭과 詰み 거리 — 개입 시점을 어떻게 결정하는가
5. 부르는 힌트와 적응형 상대 — 답을 남발하지 않고 사람이 끝내 이기게 돕는 법
6. 이를 지탱하는 구조 — 세션 goroutine, 고정 깊이 탐색, 캐시, 결정적 폴백
7. 사람이 직접 둔 뒤 바뀐 것 — 자동 힌트를 끄고, 待った와 되짚기를 넣은 이유
8. 아직 말할 수 없는 것 — 초기 상수, 지연 실측, 태그 정확도, 선행 계산

세 초안은 삭제하지 않는다. 검증한 실측과 사고 기록의 유일본이기 때문이다. 다만 “3편 작성”을 제출 진척으로 세지 않는다.
공개 대상은 위 종합편 하나뿐이다.

## 4. Zenn 형식과 공개 규칙

- 기사는 리포 루트의 `articles/`에 둔다
- slug는 12~50자의 `a-z0-9-`만 쓴다
- `topics`는 5개 이하로 둔다
- `pnpm lint`와 `pnpm zenn:preview`를 둘 다 통과시킨다
- 코드 주석은 기사에서 일본어로 옮겨 발췌하고, 원본은 GitHub 링크로 건다
- GitHub URL은 맨줄에 놓지 않고 마크다운 링크로 쓴다. Zenn의 자동 임베드가 한글 주석을 펼치지 않게 한다
- 확인하지 못한 숫자는 쓰지 않는다. 계산값과 실측값을 구분한다
- `$review-article`로 두 에이전트가 연속해서 수정 사항 0건을 낼 때까지 검토한다
- 종합편만 `published: true`로 둔다. 기존 기술 초안 3편은 `false`를 유지한다

Zenn CLI와 oxfmt의 호환성, Mermaid·메시지 블록 렌더, GitHub `main` 연동은 기존 세 초안을 만들 때 이미 확인했다.
