# 프론트엔드 — 판 · 개입 연출 · 리뷰

프론트는 **최대한 친절해야 한다.** `../shogi`의 화면은 알아볼 수는 있었지만, 이번엔 더 잘 보이고 사용자 입장에서 깔끔해야 한다.

## 1. 3D 방침 — 원근 판은 함정이다

쇼기 기물은 전부 같은 오각형이고, **한자로만 구분되며, 방향으로 선후수를 표현한다.** 원근 투영을 넣는 순간:

- 뒷줄 한자가 뭉개진다
- 상대 기물은 뒤집힌 채 세로로 압축된다
- 앞줄이 뒷줄을 가린다

**학습 앱에서 판독 부하를 늘리면 앱이 자기 목적과 싸우게 된다.**

**방침: 정사영(orthographic) 카메라 + 아주 살짝 기운 각도.** 2D처럼 읽히면서 셰이더·전환·라이팅은 전부 확보한다.

### 3D 예산을 몰아넣을 곳 — 이 2컷뿐

1. **利き(영향력) 히트맵**
   양쪽 기물의 이동 범위를 셰이더로 실시간 스칼라 필드 합성.
   → 초심자가 "왜 여기 놓으면 죽는지"를 **글 없이** 본다.
   → **LLM 설명 신뢰성 문제를 애초에 우회하는 설계.** 3D를 쓰는 정당성이 여기서 나온다.

2. **블런더 개입 순간의 연출**
   시간 정지, 위험 기물 부각, 상대 공격선을 광선으로.
   평소엔 카메라 고정, **개입 때만** 살짝 기울인다 → "혼나는 것"이 아니라 "슬로모션 리플레이"로 느껴지게. **개입형 코치 UX 반발 완화의 핵심.**

**하지 말 것:** 평가치 3D 지형(정보량 대비 화면 낭비), 메뉴 파티클 등 장식.

### 색을 쓰는 자리 — 詰み 게이지와 직전 수 표식

판 위(칸·기물)는 빛만 쓴다. 예외가 둘이고, 둘 다 **빛으로는 될 수 없어서** 예외다.

**詰み 게이지 — 테두리의 보라 불꽃.** 다른 표면이라 칸의 빛과 자리를 다투지 않고, 경고 계열인 제지형 연출과 구별되어야 하며(게이지는 플레이어에게 **좋은 소식**이다), 원래 비유인 「가스레인지」의 불꽃이 실제로 파랑~보라다. 자세한 것은 [개입 엔진 §7](01-core.md).

**직전 수 표식 — 駒를 두르는 진한 나무색 테와 붉은 점 하나.** 칸의 잔광만으로는 「무엇이 움직였나」가 안 읽히는데, **駒 표면이 판에서 제일 밝아서 그 위에는 빛을 얹을 수 없다.** 고른 駒를 칸 테두리로 표시하게 된 것과 같은 벽이고, 여기서는 駒 자체를 짚어야 해서 피할 데가 없다. 표식은 駒보다 어두워야 하고, 어두운 값은 곧 색을 고르는 일이 된다.

**테를 붉게 칠하지는 않는다.** 경고 계열은 제지형 개입에 배정된 색이라(§2), 중립 정보인 직전 수를 그 색으로 두르면 상대가 둘 때마다 위험 신호가 켜진다. 테는 판과 같은 나무 계열의 진한 값이고 **붉은 것은 점 하나뿐**이다 — 표식으로는 읽히고 경고로는 안 읽히는 크기다.

### 구현 실무

- 한자는 매 프레임 래스터라이즈 금지 → **텍스처 아틀라스로 사전 굽기.** 기물 종류는 성한 것 포함 수십 개뿐이라 MSDF보다 선명하고 싸다
- 기물 40개에 인스턴싱은 불필요. 비싼 건 그림자·포스트프로세싱 → **베이크된 접촉 그림자**로 충분
- 모바일: `devicePixelRatio` 2로 캡. 포스트프로세싱 최대 1패스
- 접근성: 세련되게 만들려다 대비를 낮추는 게 최빈 실수. **한자 최소 크기 기준을 먼저 정하고 나머지를 역산한다**

### 미학 방향

**무광 榧(카야)색 판, 판보다 밝은 기물.** 극세 그리드, 단색 기물에 한자 음각(노멀맵). 강조는 색이 아니라 **빛**으로. 다크모드 기본.

> 여기 원래 "오프화이트 판"이라고 적혀 있었는데 **틀린 지시였다.** 그대로 만들었더니 판·기물·강조가 전부 밝은 값이 되어 기물과 판의 대비가 1.13밖에 안 나왔다. 실제 대국은 반대다 — 판이 꿀색 나무이고 **기물이 판보다 밝다.** 원래 관계로 되돌리니 대비가 1.92가 되고, 덤으로 **빛을 얹을 여지가 생겼다.** 판이 흰색에 가까우면 그 위에 빛을 올릴 자리가 없다.

## 2. 대국 화면

평시엔 조용하다. 힌트도 최선수도 없다. 판 위에 상시 표시되는 것은 [囲い·전법 태그](01-core.md#7-힌트--남발하지-않기-위한-게이트)와 [詰み 게이지](01-core.md#7-힌트--남발하지-않기-위한-게이트)뿐이고, 둘 다 플레이어 쪽만이다.

개입이 걸리면 연출로 전환하는데, **두 방향의 톤이 달라야 한다.**

|        | 제지형 (블런더)                    | 제안형 (手筋)                   |
| ------ | ---------------------------------- | ------------------------------- |
| 시간   | 정지한다                           | 흐른다 — 무시하고 둬도 된다     |
| 카메라 | 살짝 기운다                        | 고정                            |
| 빛     | 위험 기물과 상대 공격선을 광선으로 | 해당 **영역**만 조용히 밝아진다 |
| 색     | 경고 계열                          | 판과 같은 계열의 밝기 차이만    |

제안형에 경고 연출을 쓰면 플레이어는 자기가 뭔가 잘못한 줄 안다. **강조는 색이 아니라 빛으로**라는 원칙이 여기서 실제로 값을 한다 — 같은 광원을 세기만 달리해 두 개입을 구분한다.

그리고 제안형은 **어느 칸인지 짚지 않는다.** 영역까지다. 칸을 짚는 순간 최선수를 보여주는 것과 같아진다.

## 3. 리뷰 화면

기존 앱은 "이 국면에서 최선수는 선수 4四金, 후수 2三飛車"처럼 표기로 말한다. **잘하는 사람에게만 통한다.** 못하는 사람은 그 국면이 눈에 그려지지 않는다. 그래서 **전부 판 위에서 보여준다.**

```
              ↖ 최선수 Top 3
     ←   현재 국면   →        (← 이전 수 / → 다음 수)
              ↘ 내가 두려던 블런더 (시스템이 물렀던 수)
```

- **네 방향 전부 클릭하면 그 분기로 들어가 계속 진행할 수 있다.** "이렇게 뒀으면 어떻게 됐을지, 그 다음엔 어떻게 됐을지"를 전부 따라갈 수 있어야 한다. 분기 구조는 [`edges` 테이블](02-architecture.md#4-데이터-모델--그래프-db를-쓰지-않는-이유) 그대로다
- 되돌아가면 분기가 다시 보인다
- 이동은 반드시 **애니메이션.** 말이 갑자기 바뀌면 초심자는 무엇이 변했는지 못 본다. 이게 초보자를 위한 길이다
- 각 수에 `eval_by_depth` 스파크라인 — **"얕게 보면 좋았는데"**를 그림으로

대국이 끝난 뒤뿐 아니라 **대국 도중에도** 지금까지의 수를 이 화면으로 확인할 수 있다.
