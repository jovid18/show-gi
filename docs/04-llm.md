# LLM 계층 — 심사 기준 6번에서 이긴다

## 1. 대원칙

> **LLM에게 판단을 맡기지 않고 표현만 맡긴다.**

학습 앱에서 설명이 틀리면 초심자는 검증할 능력이 없어 틀린 것을 그대로 배운다. 그래서 분석은 **엔진 기반**이고, LLM은 그 분석 결과를 **말로 바꾸는 역할만** 한다. 그러려면 데이터 저장 방식과 쇼기 도메인 조사가 선행되어야 한다 — 그게 [카테고리 온톨로지](01-core.md#3-블런더-카테고리-온톨로지--진짜-승부처)와 [`edges` 스키마](02-architecture.md#4-데이터-모델--그래프-db를-쓰지-않는-이유)다.

**LLM 입력은 항상 구조화 데이터다** — 카테고리, 잡히는 말, 利き 수, Δ승률, 사용자 레벨, 이미 아는 개념. 판을 그대로 던지고 "평가해줘"라고 하지 않는다.

**프롬프트도 출력도 일본어다.** 사용자가 일본인이라 당연하지만, 실무적으로도 그렇다 — 프롬프트에 한글이 섞이면 출력이 한글로 새고, `temperature=0` 캐시 키가 갈라져 [Tier 0](#2-비용-계층)이 안 맞는다. 쇼기 용어는 애초에 일본어가 원전이라 번역 손실도 없다.

**LLM이 하는 일:** 게임 중간중간 "이걸 써먹으면 좋겠다" 싶은 지점에서 코멘트를 준다. 그 판단 자체는 엔진과 [힌트 게이트](01-core.md#7-힌트--남발하지-않기-위한-게이트)가 하고, LLM은 그 사람 수준에 맞는 문장을 만든다.

## 2. 비용 계층

```
Tier 0  explain_cache 히트                → 0엔
Tier 1  카테고리 + 레벨 조합 각색          → 소형 모델
Tier 2  이 국면 고유 사정                  → 대형 모델
```

캐시 키 = `hash(category, level_bucket, piece, 국면특징 버킷)`.
**블런더 카테고리는 유한하므로 설명의 대부분은 사전 생성 + 캐싱으로 덮인다.**

## 3. OrcaRouter

OpenAI 호환 메타 라우터 / AI 게이트웨이. 해커톤 요구사항이기도 하다.

- 200+ 모델을 엔드포인트 하나로, 토큰 마크업 0
- `model="auto"` → 요구 능력(tools/vision/JSON)을 충족하는 **가장 싼 모델** 자동 선택
- LinUCB 컨텍스추얼 밴딧 + 오프라인/온라인 하이브리드 학습. RouterArena 정확도 75.5%
- 가드레일, 에이전트 방화벽, 자동 failover, 관측성

```js
import OpenAI from "openai";
const client = new OpenAI({
  baseURL: "http://localhost:8000/v1",
  apiKey: "sk-orca-...",
});
const r = await client.chat.completions.create({
  model: "auto",
  temperature: 0,        // 캐시 히트 유도
  messages: [...],
});
```

> 서버는 Go지만 OrcaRouter는 OpenAI 호환 **HTTP**라 그냥 POST하면 된다. 위 JS는 참고용.

**우리에게 특히 유용한 2가지:**

1. **크로스 프로바이더 프롬프트 캐시** — `temperature=0` 또는 seed 고정 시 반복 요청은 캐시에서 나온다. `x-orca-cache: HIT`, **비용 0.** → §2의 Tier 0을 우리가 직접 다 구현할 필요가 없다.
2. **`GET /v1/analytics/savings?baseline=gpt-4o&days=7`** — "항상 GPT-4를 썼다면 vs 실제" 비교를 대시보드 타일로. → **심사 기준 6번 슬라이드에 스크린샷 한 장으로 끝.**

**응답 헤더로 확인:**

- `x-orca-resolved-model` — 실제 선택된 모델
- `x-orca-cache` — HIT / MISS

## 4. RAG — 코퍼스는 처음부터 새로 만든다

7일 안에 제대로 된 RAG 파이프라인은 무리다. 대신 **pgvector 지식 테이블**로 좁힌다. `kb_chunks`에 임베딩해서 Tier 1/2 프롬프트에 근거로 붙이고, **검색 결과가 없으면 붙이지 않는다**(환각 방지).

### `../shogi`의 데이터는 한 줄도 쓰지 않는다

세 가지 이유가 각각 독립적으로 결정적이다.

1. **출처를 신뢰할 수 없다.** 저쪽 콘텐츠의 원전은 개인 블로그 강좌다. 취미 학습용으로는 충분했지만, **틀린 설명이 초심자에게 그대로 전달되는 제품**의 근거로 쓸 수는 없다. 이 제품의 존재 이유가 "설명이 틀리면 초심자는 검증할 수 없다"인데 코퍼스가 검증 안 된 글이면 자기모순이다.
2. **저작권.** `tesuji.ts` 208문은 시판 서적을 디지털화한 것이다. **이 레포는 퍼블릭이다.** 신뢰성 이전에 옮기면 안 된다.
3. **언어.** 설명문이 전부 한국어다. 일본어 질의로 검색하는데 코퍼스가 한국어면 임베딩 유사도가 무너지고, 근거로 붙여도 출력이 한글로 샌다.

### 신뢰 계층 — 사실은 사람 글에서 가져오지 않는다

| 계층             | 무엇                              | 출처                                                                                                                                | 검증                                                      |
| ---------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| **1. 수순·국면** | 정석 수순, 囲い 완성형, 手筋 국면 | 공개 **정석 파일**(やねうら王 등)과 프로 기보 DB                                                                                    | **자체 엔진으로 재검증.** 합법성 + 평가치가 주장과 맞는지 |
| **2. 용어·개념** | 囲い/전법 이름, 정의, 장단점      | **日本将棋連盟 공식** 용어·규칙 페이지, **일본어 위키백과**(CC BY-SA — 출처 표기하면 퍼블릭 레포에 실을 수 있는 유일한 서술형 소스) | 사람이 읽고 확인. 근거 URL을 chunk에 박는다               |
| **3. 태그 체계** | 태그 목록과 이름                  | 将棋ウォーズ의 전법·囲い 태그명                                                                                                     | 이름만 참고. 콘텐츠는 가져오지 않는다                     |

**핵심은 계층 1이다.** 수순의 신뢰성은 사람이 쓴 글보다 **엔진 정석 파일 + 자체 검증**이 압도적으로 높다. 囲い는 "이렇게 두면 美濃다"라는 설명이 아니라 **최종 배치의 좌표 집합**으로 정의하고, 엔진으로 도달 가능성을 확인한다. 그러면 블로그가 필요 없어진다.

**쓰지 않을 것:** 개인 블로그·번역 경로가 불분명한 2차 자료, 서적 스캔/디지털화, 유료 서비스의 해설 콘텐츠.

### 출처를 스키마에 박는다

```sql
kb_chunks (
  id, title, body,               -- body는 일본어
  tags text[],
  source_url text,               -- 없으면 프롬프트에 붙이지 않는다
  source_license text,           -- 'CC-BY-SA-4.0' | 'official-reference' | 'engine-derived'
  verified_by text,              -- 'engine' | 'human' | null
  embedding vector(1536)
)
```

`verified_by`가 비면 검색에 걸려도 **프롬프트에 붙이지 않는다.** 미검증 지식이 조용히 설명으로 새는 경로를 코드가 아니라 스키마에서 막는 것이다. 발표에서 "판단은 엔진"을 말할 때 이 컬럼이 근거가 된다.

### 규모

태그 수만큼만 있으면 된다 — 囲い 10–14 + 전법 8–10 + 手筋 15–20 + [블런더 카테고리](01-core.md#3-블런더-카테고리-온톨로지--진짜-승부처) 7 ≈ **50개 항목 × 일본어 1–2문단.** 하루면 만들고 검증할 수 있는 크기다. 양을 늘리는 것보다 **전부 출처가 붙어 있는 것**이 먼저다.

## 5. 계측 — 발표 자료가 되는 숫자

`interventions` 테이블의 `explain_tier` · `cost_yen`에서 집계한다.

- **개입 1회당 평균 ○엔**
- 캐시 히트율 (Tier 0 비율 + `x-orca-cache: HIT` 비율)
- savings 위젯 스크린샷

> **절감을 2단계로 보여주는 것이 핵심이다.** 라우터만 쓴 팀은 많을 것이다. **"구조적으로 호출 자체를 줄인 뒤, 남은 것만 최적 모델로 라우팅"** 하는 팀은 드물다.
