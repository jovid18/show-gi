# 개입 엔진 — 제품의 코어

이 문서가 제품 그 자체다. 나머지 문서는 전부 이걸 지탱하는 장치다.

## 1. 루프

```
평소엔 힌트 없음 → 플레이어 착수 → 판정
   ├ 정상        → 상대 수 (선행 계산돼 있어 즉시)
   └ 블런더      → 시간 정지 · 연출 · 카테고리 설명 · 롤백 → 다시 두기
                    ↓
              개입 로그 누적 → 약점 프로파일 + 실력 추정
```

**기본적으로 최선수는 보여주지 않는다.** 그것은 실제로 도움이 되지 않는다. 보여주는 것은 "왜 방금 그 수가 나쁜가"뿐이다.

### UI 결정: 착수 직후 롤백

착수 **전** 확인(2단계 확정 UI)은 리듬을 죽인다. 쇼기에는 「待った」 문화가 있어 **착수 직후 롤백**이 자연스럽게 수용된다. 체스보다 유리한 조건이다.

---

## 2. 판정식

평가치(cp)를 그대로 쓰지 않고 **승률로 변환한 뒤 낙폭**을 본다. cp는 우세 구간에서 의미가 압축되어 −800이 국면마다 다른 뜻이 된다.

```
WR(cp) = 1 / (1 + exp(-cp / K))          # K는 실측 보정 [미확정: 초기값 600]
Δ      = WR(before_best) - WR(after_move)
개입    = Δ > threshold(level)
```

레벨별 임계치 초기값 — 실측 후 조정한다:

| 구간 | 대상      | 임계치                                  |
| ---- | --------- | --------------------------------------- |
| 입문 | ~15급     | Δ 25%p                                  |
| 초급 | 10~14급   | Δ 18%p                                  |
| 중급 | 5~9급     | Δ 12%p                                  |
| 관찰 | 초반 20수 | **개입 안 함** — 飛/角 공짜 헌납만 예외 |

초반을 풀어두는 것은 요구사항이자 **실력 관측 구간**이기도 하다. 플레이어가 비차나 각을 던지는 짓만 안 한다면 어느 정도 자유롭게 두게 둔다.

## 3. 블런더 카테고리 온톨로지 ← 진짜 승부처

엔진은 "−800점"까지만 말한다. **카테고리가 있어야** ⑤ 약점 프로파일이 성립하고, LLM에게 판단을 맡기지 않을 수 있다. **전부 결정적 룰 + 엔진 피처로 분류한다.**

| 카테고리                      | 판정 룰 (초안)                                                 |
| ----------------------------- | -------------------------------------------------------------- |
| 타다스테(공짜 헌납)           | 착수 칸이 상대 利き 有 · 내 利き 無, 또는 교환차가 −1말 이상   |
| 옥 주변 수비 방치             | 옥 주변 8칸 방어 利き 합 감소 && 상대의 옥 주변 공격 利き 증가 |
| 駒得에 눈이 멀어 옥 안전 무시 | 이 수로 딴 말 가치 > 0인데 Δ가 임계치 초과                     |
| 追う手 (필요 없는 王手)       | 王手인데 후속 詰めろ가 없고 Δ 손해                             |
| 詰めろ 놓침                   | 착수 전 국면에 mate 존재(엔진 mate 탐색) && 착수 후 소멸       |
| 二枚換え 손해                 | 2교환 1의 가치 역전                                            |
| 정석 이탈 후 방향 상실        | `edges.tags`에 전법 태그가 있던 라인에서 이탈 && Δ 손해        |

> 미분류(`other`)를 반드시 허용한다. 억지로 끼워 맞추면 설명이 틀리고, 그게 이 제품에서 가장 큰 실패다.

카테고리 목록 확정은 [미결](05-roadmap.md#미결-사항).

## 4. 레이턴시 — 플레이어가 고민하는 동안 계산한다

플레이어 차례가 시작되는 **즉시** 선행 계산을 건다.

1. 현재 국면 MultiPV=8, depth 14 → 상위 8수의 착수 후 평가 확보 (`positions` 캐시에 적재)
2. 상위 3수 각각에 대해 **상대 응수까지** 미리 계산 → 정상 착수 시 상대 수 지연 0
3. mate 탐색은 별도 슬롯 → 詰み 게이지 (§6)

플레이어가 상위 8수 밖(=대개 나쁜 수)을 두면 그때 depth 10 단발 계산(≈150ms). 개입 판정은 정밀도보다 속도가 중요하니 이걸로 충분하다. 초반 국면은 `positions` 캐시 히트라 계산 자체가 없다.

엔진 프로세스는 **풀로 띄운다** — 하나로 돌리면 개입 판정이 상대 수 계산 뒤에 줄을 서서 체감 지연이 생긴다.

## 5. 실력 추정 — 개입을 측정 이벤트로 뒤집는다

개입은 실력 측정을 오염시키는 것처럼 보이지만 반대다. **개입 직전 "원래 두려던 수"가 개입 없는 순수 실력 신호**다 (`game_moves.retracted_usi`).

수 하나하나가 라벨링된 문항이 된다 — `(MultiPV 내 순위, Δ승률, 국면 태그)`. 대국 한 판이 100문항 이상이라 **대국 결과보다 훨씬 밀도 높은 실력 추정 데이터**가 된다.

레이팅은 온라인 갱신(Elo류 또는 Bayesian). **[미확정: 갱신식]**

카테고리별 발생률이 그대로 약점 프로파일이 되고, 그것이 §2 임계치와 [LLM 설명 깊이](04-llm.md)의 입력이 된다.

> 개입을 "측정 방해"가 아니라 **"측정 이벤트"**로 설계하면 ①과 ③이 충돌 대신 시너지가 된다. 15초짜리 인사이트지만 발표에서 기억에 남는 부분.

## 6. 적응형 상대 — "지지만 던지지 않는다"

목표: 플레이어보다 **조금씩** 못하게, 그리고 그 과정이 자연스러워야 한다.

```
target_band = [+100, +300] cp   (플레이어 우세 쪽. 플레이어 레이팅에 따라 조정)
후보 = MultiPV k=5
  1. 자살수 필터: 착수 후 상대(=플레이어)에게 공짜로 잡히는 수를 제거   ← "던지지 않는다"
  2. 남은 후보 중 착수 후 평가치가 target_band에 가장 가까운 수 선택
  3. 플레이어가 잘 두면 밴드가 자동으로 좁아짐 → 컴퓨터도 강해짐
```

기존 약한 AI와 갈리는 지점이 **1번 필터**다. 플레이어의 블런더는 §1 개입이 막아주므로, **컴퓨터가 무리해서 말을 던질 필요가 없다.** 조금씩 안 좋은 선택을 쌓는 것만으로 플레이어가 이기게 만들 수 있다.

**오프닝은 랜덤으로 돌린다.** 초반 20수는 정석 북에서 전법을 무작위 선택(三間飛車 / 居飛車 / 振り飛車 / 棒銀 …)해 플레이어가 다양한 형태를 연습하게 한다. 수순은 **공개 정석 파일에서 가져와 자체 엔진으로 재검증한다** — `../shogi`의 전법 데이터는 쓰지 않는다 ([LLM 계층 §4](04-llm.md#4-rag--코퍼스는-처음부터-새로-만든다)).

## 7. 힌트 — 남발하지 않기 위한 게이트

모든 수마다 알려주면 도움이 되지 않는다. 발동 조건이 곧 설계다.

| 힌트                          | 발동 조건                                                                                  | 표현                                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| **手筋** (両取り·十字飛車 등) | 1위와 2위의 평가차 > 300cp **그리고** 그 수가 태그된 手筋 패턴 — 즉 "여기밖에 없다"일 때만 | 판 위에 해당 영역 표시                                                                        |
| **詰み 게이지**               | 매 수 후 mate 탐색. 거리 7→5→3→1                                                           | 보드 **테두리 발광**이 점점 강해짐. 가스레인지에 불이 붙듯. **수순도 手数도 알려주지 않는다** |
| **囲い·전법 감지**            | 배치 패턴 매칭 (美濃 = 玉2八 + 金3八 + 銀3七 …)                                            | 将棋ウォーズ처럼 판 위에 이름 표시. **플레이어 쪽만** — 컴퓨터의 수는 알려주지 않는다         |

手筋 패턴 판정도 룰이다 — 예: 両取り = 한 수로 고가치 말 2개 이상을 새로 공격. 囲い는 해설문이 아니라 **최종 배치의 좌표 집합**으로 정의하고 엔진으로 도달 가능성을 확인한다. 그러면 2차 자료가 필요 없어진다.

임계치 300cp는 아직 감이다 — [미결](05-roadmap.md#미결-사항).
