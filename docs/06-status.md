## 1. 현재 구현

개입 판정과 일본어 설명은 결정적 룰·엔진 평가치·템플릿으로 처리한다. LLM은 기보 서식 정규화와 사진 판독에만 사용한다.
기보는 룰 엔진으로 전수 검증하며, 사진은 국면 검사와 사용자의 확인을 거친다.

## 4. 검증 범위

- 2026-09-08 재구축 기록에서 DNS·TLS·OIDC·이미지 빌드·ECS 배포·ALB 헬스체크·RDS를 확인했다. [§133](journal/121-140.md)
- 대국 WebSocket, 엔진과 mate solver, 개입 연출·설명은 과거 프로덕션 시험 기록이 있다. [§10·13·14·15](journal/06-20.md)
- 대인전 매칭·레이팅·실력 추정 경로의 프로덕션 시험은 [§105](journal/101-120.md)에 있다. 상수의 적절성은 검증되지 않았다.
- `c6g.large`의 대인전 용량은 분석 1대에서 6판 지속·8판 포화, 2대에서 12판 지속·14판 포화였다. 당시 조건은 [§109·113](journal/101-120.md), [§122·123](journal/121-140.md)에 있다. 현재 절약 모드의 용량으로 사용하지 않는다.
- 사진 판독의 8장 시험은 작은 표본이다. 실제 사용자 사진에 대한 정확도는 [미확정]이다.
- depth 12로 되돌린 뒤의 프로덕션 지연, 문항 큐 분리 후 실제 대기 시간, 공유 카드 미리보기는 [미확정]이다.
- 手合割 기준점 표(`internal/handicap`)는 depth 14 실측이다. depth 12 재측정 전까지 [미확정]이다. [§140](journal/121-140.md)

로컬 검증 명령은 [CLAUDE.md](../CLAUDE.md), DB·엔진 테스트 환경변수는 [서버 README](../apps/server/README.md)에 있다.
환경변수 없이 생략된 테스트를 전체 검증 완료로 보고하지 않는다.

## 5. 남은 일

완료된 로그인·실시간 실력 추정·밴드 조절·오토스케일·캐시·문항 큐는 §1에만 표시한다.
다음 작업은 실제 대국에서 드러난 문제를 우선한다. 구현된 기능의 재검증과 아직 구현하지 않은 기능을 구분한다.

### 먼저 확인할 것

1. 프로덕션에서 `023` 적용 여부와 문항 큐 동작을 확인한다. 완료 전까지 §3의 [미확정]을 유지한다.
2. 手合割 기준점 표를 depth 12로 다시 잰다(`baseline_measure_test.go`). 탐색 지연과 문항 큐 분리 후 대기·처리량도 측정한다. 과거 비버스터블 용량표를 현재 값으로 쓰지 않는다.
3. 사람이 둔 판으로 개입·힌트·난이도를 다시 평가한다. [플레이테스트 기록](playtests/README.md)과 [§39](journal/21-40.md)의 재채점 장치를 사용한다.

### 확장이 필요할 때

상호작용 티어를 여러 대로 늘리기 전에는 방 소유권·라우팅·드레이닝을 설계해야 한다.
방이 프로세스 메모리에 있어 현재는 1대만 운영한다. DB·Redis·스티키 라우팅 중 선택은 [미확정]이다.

다음 수직 확장 측정은 `c6g.xlarge`에서 코어와 `ENGINE_POOL_SIZE`를 함께 늘리는 시험이다.
2 vCPU에서 풀만 4로 늘린 시험은 개선되지 않았다([§110](journal/101-120.md)).
부하 시험 전에는 절약 모드를 해제하고 인스턴스 타입·구매 방식·메모리·탐색 깊이를 기록한다.

## 7. 알려진 부채

| 항목                     | 상태·영향·대응                                                                                                                                                                                                                                                                                                       |

## 8. 열린 결정

| 결정                          | 현재 방침과 재검토 조건                                                                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| API 이미지 distroless 전환    | 보류. 엔진 라이브러리는 충족할 수 있으나 셸과 ECS Exec을 잃는다. `/metrics`의 다른 관측 경로를 확보하면 재검토한다. [§134](journal/121-140.md)                           |
| Terraform 업그레이드·OpenTofu | S3 네이티브 잠금으로 DynamoDB를 대체할지 미결이다. 현재 구성과 호환성을 검토해야 한다.                                                                                   |
| 가져온 기보의 실력 반영       | 포함하는 것이 현재 방침이다. 기보 소유자를 검증할 수 없어 타인의 기보도 반영될 수 있다. 제외할 경우 `games.imported_from`으로 구분할 수 있다. [§126](journal/121-140.md) |
| 서양식 표기 기보              | 현재는 받지 않는다. 도입하려면 LLM 대신 Go에서 좌표를 결정적으로 변환한다. [§126](journal/121-140.md)                                                                    |
| 상호작용 티어 확장            | 방 상태를 공유하거나 소유 인스턴스로 라우팅하는 방식이 필요하다. 방식과 비용은 미결이다.                                                                                 |

엔진 선택, sqlc, 후보 수 k=10, 지식 출처, 상대 玉만 표시하는 게이지는 완료된 결정이다.
근거는 [저널 목차](journal/README.md)와 [태그 출처](09-tags.md)에서 찾는다.
